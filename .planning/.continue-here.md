# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each one was discovered through failure in this
> session. Acknowledge each explicitly before proceeding.

- [ ] CONSTRAINT: `/tmp` is a 3.6GB shared tmpfs and the Flutter tool leaks ~13MB per test file — **`/tmp` is a full tmpfs at `80%`**, three times this session. When it fills, `flutter test` fails **every test file at load** with no useful message, and Gradle fails with `Disk quota exceeded`. The repo-local `TMPDIR` does NOT help Gradle: the asset compressor writes through `java.io.tmpdir` and ignores `TMPDIR`. **Mitigation: `rm -f /tmp/.9adb*.so; rm -rf /tmp/flutter_tools.*` before any long test run.** `tool/verify.sh` warns below 512MB and recognises "Disk quota exceeded" as a full disk rather than a broken build.
- [ ] CONSTRAINT: Hive writes inside a `testWidgets` body **deadlock** — the write never completes and holds the box lock. You cannot tap a save button. **Mitigation: drive storage through `tester.runAsync`, cover persistence at the provider layer and the UI half in widgets, and leave a comment at each site.** `runAsync` is reentrant-hostile: always await before calling again. `(await tester.runAsync(f))!` — the `!` wraps the awaited value, not the Future.
- [ ] CONSTRAINT: `design_system_test.dart`'s `_colourDistance` returns a weighted **squared** distance compared against `150`, so the real threshold in ordinary distance terms is ~**12.25**, not 150. I mis-read this and briefly concluded Stage 0b was mathematically impossible. **Mitigation: read the metric before reasoning about it.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| `git add -A` before splitting commits | Swallowed `tool/verify.sh` into a code commit, so the message described only part of the change | advisory | `git reset HEAD -- <path>` then commit separately |
| Slicing a Dart test file on its **last** brace | Twice inserted a test group *inside* a helper function instead of `main()`, producing `dead_code` analyzer errors and silently dropping tests | advisory | Anchor insertion on a unique marker like `\nWidget _spendApp({`, and assert the marker exists before writing |
| `git checkout -- <test file>` to "clean up a debug edit" | **Deleted the entire new test group.** Cost two rewrites | advisory | Never `git checkout --` a file you have written new tests into; `git stash` a debug patch instead |
| Testing a screen only at 412dp | Missed **two 1px overflows** in the month summary card that no test had ever found | blocking | Any new or changed UI on a tab is tested at **both** 412x915 and 360x640 |
| Date-dependent assertions | One pre-existing test asserted the literal `'September'` and broke at midnight on the 1st; one of mine asserted a suggestion reason that changes with the season | blocking | Derive expected text from the clock or from the code under test; never hardcode a calendar value |
| Verifying a finding by disabling code without asserting the replace matched | A bisect "disproved" a hypothesis because the `str.replace` had silently no-op'd | advisory | `assert old in s` before every `str.replace` in a patch script |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.

## Stage 7 — Budgets (`17-budgets`)

**Both scopes:**

- **App-level, per expense category** — the 10 `ExpenseCategory` values at
  `expense_category_meta.dart:12`
- **Journey-level, one limit per journey** — optional field on the journey model

**Periods: month / week / year.** No per-product budgets.

**Journey expenses and app budgets are separate pools.** A trip expense does NOT
count against an app-level category budget.

Compute against `provider.currentMonth` (`transaction_provider.dart:85`) so budgets
match the month the user is browsing. Weekly and yearly derive from the same spend
data.

**Store in `SharedPreferences`, not Hive** — follow the exact pattern at
`settings_provider.dart:47`, `getInt`/`setInt` per key. No new box, no migration.

**No manual reset button**; the period is the reset. A user-resettable budget
stops being a limit and becomes a suggestion.

**Overspend notifies, it never blocks.** Use `NotificationService`
(`lib/services/notification_service.dart`, already initialised in `main.dart:16`).
Adding an expense over budget must always succeed.

**Read trip expenses, not settlement ticks.** `journey_provider.dart:463`
documents that settling writes no transaction, deliberately. A budget must not
count a reimbursement.
